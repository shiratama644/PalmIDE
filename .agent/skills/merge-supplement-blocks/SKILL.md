# Skill: 補足ブロックの本文統合（Merge Supplements）

`docs/*.md` 等に散在する `> 🆕 詳細化補足` ブロックを、各ファイル内の適切なサブセクションへ解体・編入する統合力。**一読で通読できる文書にすることが目的**（「一度は正、二度目は本文」を徹底）。

## 適用前提

- 解体対象ブロックは **Phase 4〜5 の `> 🆕` / `> ⚠️`**
- 統合対象の内容（決定・根拠・不採用案）はすべて `PHASE5_report.md` / `REVIEW_DESIGN.md` / `PHASE4_0_gaplist.md` に根拠がある

## 手順

1. **棚卸し**: `grep -c '^> 🆕\|^> ⚠️' docs/*.md` でブロック総数を把握する（今回は39件だった）
2. **マッピング設計**: 各ブロックについて「編入先サブセクション」を `## 4. 該当節.1 概要` の形式で先に決める（MERGE_DIFF_REPORT.md §4 の対応表が実績例）
3. **字面整理**:
   - 決定済み = 本文に「〜を確定とする」。`>> - 対象/種別/根拠` の装飾行は捨てる
   - 不採用案 = 1〜2文で「採用しなかった理由」を本文に残す（完全削除しない）
   - ⚠️ 履歴ブロック = **消す**。判断詳細は `docs/` 旧コミットに残るため history から復帰可能
4. **編集**: 各ファイルへ `Edit` で直接編入（新規節は既存節末尾に `.N` 番で）
5. **リンク修正**（合わせ技）: 実在しないパス（例: `uploads/Local_AI_Agent.md`）は実在名に修正（`uploads/Local%20AI%20Agent.md`）
6. **検証**: skills/verify-doc-integrity の 4ステップを実行
7. **差分レポート生成**: skills/diff-review-report のテンプレで `MERGE_DIFF_REPORT.md` 相当を作成

## 失敗パターン（過去の教訓）

- ブロック内のコードブロックを「要約」して独自の書き換えを入れる → **NG**。コードは一字一句貼る
- 2つのブロックが同じ内容（例: G05 の Phase 4 案と Phase 5 決定）を両方残す → **決定版のみ**を採用
- リンク先だけ編集して mergetool のような構造比較をしない → Rule 05-B のリンク検証は必須
