# Skill: 差分レビューレポートの作成

変更が3ファイル以上または判断を伴うとき、必ず作成するレビュー用レポートの手順。

## 形式（MERGE_DIFF_REPORT.md 準拠）

```markdown
# 統合差分レビュー報告書 — X → Y

> 作成日: YYYY-MM-DD / 対象: （旧→新の範囲）
> 目的: 何をレビューしてほしいか1行で

## 1. 統合の方針        ― 数化できない判断の宣言（箇条書き5点程度）
## 2. 全体サマリ        ― 総行数、ブロック数、ファイル数の表
## 3. 行数変化（ファイル別）― 旧/新/差分/主な変化理由の4列表
## 4. 補足ブロックの行き先一覧 ― 全 N ブロックの対応表（#・ID・対象・内容・編入先・扱い）
## 5. 意図的な変更点     ― (1) 本文改変の列挙 (2) 削除情報の列挙 (3) 圧縮・簡素化の列挙 (4) リンク修正の列挙
## 6. 機械検証結果       ― grep/リンク/識別子の3検証の結果をコマンドと期待値つきで
## 7. レビューポイント    ― 人間判断を仰ぐ RP- 番号を表で。理由と考えうる懸念を必ずセット
## 8. まとめ
```

## 作成手順

1. `wc -l` で旧新の全ファイル行数を取る
2. `grep -c` でブロック数の変遷を確認する
3. `git diff --stat` で変更範囲を確定する
4. 差分を「編入（決定）/ 編入（参照）/ 削除 / 圧縮」の4分類に仕分ける
5. 人間判断を仰ぐ事項は RP-N として表に集約し、**理由と懸念を必ずセット**で書く

## 品質基準

- 数値は `wc` / `grep` の実測値のみ使う（推定で書かない）
- 「変えたつもり」ではなく「実際に変えた場所」を `git diff` で確認してから書く
- レポート本文は「削除した」か「まとめた」かを正確に区別して書く
