# Rule 05: 完了前の検証チェックリスト

> 優先度: HIGH。**「作成した」で終わらせず、必ず以下を機械的に通過させてから報告する**

## 1. コミット/報告前の4項目

### (A) 許容外文字の混入チェック（引用ブロック `^>` のみ対象。本文見出しは誤検出させない）
```bash
grep -nH '^>[^>]*\(🆕\|⚠️\)' new/*.md | grep -v 'new/README.md' && echo "NG: ブロック残存" || echo "OK"
```

### (B) リンク検証（全内部リンクが実在すること）
```bash
cd new
grep -ohr '](\./[^)]*)' *.md | sed 's/](\.\///; s/)$//; s/#.*//' | sort -u |
  while read -r f; do [ -f "$f" ] || echo "BROKEN: $f"; done
cd ..
# 期待: 出力なし（すべて実在）
```

### (C) 不変値の保持（Rule 02 のスニペットを実行し MISSING 0件）
（Rule 02 §2 のスクリプト参照）

### (D) 変更含意の差分見読み
```bash
git diff --stat HEAD~1 HEAD 2>/dev/null || git status --short
# 狙いではないファイルが含まれていないかを目視
```

## 2. 報告のテンプレート（チャット応答）

作業完了時は以下の4点セットで簡潔に報告する。

1. **変更ファイル一覧**（パスのみ）
2. **機械検証結果**（(A)〜(C) を「OK/NG + 件数」で）
3. **意図的に変えた点**（本当に変えたつもりの場所だけ。偶発的な編集はないか自己疑う）
4. **人間判断を求める事項**（RP-系があれば箇条書き）

## 3. 長文レポートの必要性の判断

- 変更が `new/` の 2ファイル以下 ＆ 機械検証で OK なら、チャット応答のみでよい
- **3ファイル以上の変更 or 判断を伴う変更** の場合は、別途 `*_REPORT.md`（MERGE_DIFF_REPORT.md の形式）を作成してレビュー可能な形にする
